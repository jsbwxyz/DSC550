* Regression: RMSE, MAE, R²


4. Start simple, then increase complexity


* Logistic regression / decision tree / Naive Bayes first

Hi Jeremy,


You are very close. Model selection is not so much “calculating the hyper-parameters” as it is **choosing candidate models, tuning their hyper-parameters, and comparing their performance** using a validation approach such as cross-validation.


A good way to think about it is:


1. Choose several reasonable candidate models

2. Tune their hyper-parameters on the training data

3. Compare them using the metric that fits the problem

4. Select the model that performs best **and** makes sense for the data

5. Evaluate that final choice on the holdout test set


Also, hyper-parameters do not describe the data itself; they control how the model learns from the data.


You are asking the right questions.

Hi Jeremy,


You are thinking about this correctly. If the sentiment labels were already generated by RoBERTa, then those labels should be treated as model-generated labels, not ground-truth human labels. That does not necessarily invalidate the project, but it changes how you should frame it.

The key issue is to avoid data leakage. You should not use RoBERTa-generated outputs, such as sentiment or confidence score, as predictors when trying to predict sentiment. Instead, your predictors should come from information available before sentiment is assigned, such as:


    entity text
    keyword text
    entity type
    article title or article text features
    mention count
    source/domain
    publication date or time-based features


Then the target can still be the sentiment label, but you should clearly state that the labels are weak labels or pseudo-labels generated by RoBERTa. In that case, your model is essentially learning to approximate or operationalize the RoBERTa labeling process for your specific niche, rather than learning from independently verified human sentiment labels.


You are also correct that having organic/human-labeled sentiment data would be stronger. That is exactly why high-quality labeled data is expensive: it provides independent ground truth rather than relying on another model’s output.

Hi Jeremy,


You are thinking about it in the right way. Validation does come after training, but train-test contamination usually happens earlier, when information from the validation set is allowed into preprocessing or feature engineering.


A common real-world example is fitting scaling, imputation, PCA, or feature selection on the full dataset before splitting. In that case, the training pipeline has indirectly used information from the validation data.


This is a good area for independent study. As you read, keep tracing the pipeline step by step and ask yourself whether each step was fit only on the training data. That habit will help you catch leakage issues quickly.
